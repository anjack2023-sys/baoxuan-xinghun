---

## 1. 赛制名称

**抢5分／抢8分**（目标分由模式选择：5 或 8）。

---

## 2. 单局得分（写入比赛圈）

| 单局结果 | 分值 | 机制侧定义（对齐现有结束原因） |
|----------|------|--------------------------------|
| **正常胜利** | 胜方 **+2** | `spinout` 或 `timeout(momentum)` 产生唯一胜者（非出界）；日后爆裂/陷阶胜若单列，默认同档 **+2**（待多终结序定稿） |
| **击飞／出界胜利** | 胜方 **+3** | **凡** `ringout` 产生唯一胜者即 +3 |
| **平局** | 双方各 **+1** | 超时动量差 ≤ ε；或双方同时出界/同时停转等现有 DRAW |

> **用户原话（2026-10-26，经游戏策划转达）**：「+3不限于XTR；凡出界胜都+3」。  
> 废止「仅 XTR +3、普通出界 +2」提案。XTR 若日后实装，只作表现/成就标签，**不加额外分**（仍计 ringout +3）。Feel85 冻结常数不动。

---

## 3. 获胜条件

- 任一方 **分数 ≥ 目标分（5 或 8）且严格领先** → **立即获胜**（不等打完剩余出场）。
- 未达「达分且领先」则继续下一局。

---

## 4. 出场与盲选

### 4.1 常规阶段

- 双方各有 **5 只**陀螺。
- 从中选出 **3 只**进入常规出场池；**每只出场一次**（用过即消耗，不可重复出场，直到整池重置）。

### 4.2 盲选加赛

- 当常规 3 只用尽仍未决出「达分且领先」时：从 **剩余 2 只**中各自秘密选择 1 只。
- **双方锁定后同时揭晓**，再打一局。

### 4.3 全部用完后的重置

- 若 5 只均已出场仍未决：
  - **5 只全部恢复可选**；
  - 每只再获得 **一次**出场机会；
  - **仍采用盲选**（秘密选 → 锁定 → 同时揭晓）继续，直到有人达分且领先。

设计意图：保留出场消耗 + 隐藏选择博弈，并保证未决比赛可继续。

---

## 5. 与单局物理的接口（给实现）

| 接口 | 约定 |
|------|------|
| 单局胜负源 | 仅信任 `Reason`：`ringout` / `spinout` / `timeout…` + `Winner` |
| +3 触发 | `Reason == ringout` 且存在唯一胜者 |
| +2 触发 | 唯一胜者且非 ringout |
| +1/+1 | `Winner == -1`（DRAW） |
| Feel85 / Grade1 表 | **禁止**因计分改动冻结常数或 k 表 |

大厅→选螺→准备→拉绳→战斗→结算的 **流程与文案** 归游戏策划；本文件只定 **分值与出场消耗规则**。

---

## 6. 验收标准（草案，策划可加细）

1. 目标分 5 与 8 两模式可切换；达分且领先立即结束比赛。  
2. 出界胜 +3、非出界胜 +2、平局各 +1，HUD/结算可读。  
3. 常规 3 出场不可重复；加赛仅剩余 2 盲选；5 用尽后整池重置且仍盲选。  
4. 盲选：锁定前对方不可见；同时揭晓后再进入准备/发射。  
5. 单局物理回归（ContactWeight 等）不被比赛圈改动破坏。

## 8. 补锁定（用户原话 · 2026-10-26）

## 9. 计分口径锁定（用户原话 · 2026-10-26）

- **+3**：凡出界胜（`ringout`），**不限于 XTR**。
- **+2**：非出界的唯一胜者（停转 / 超时动量等）。

## 11. 多终结统一判定序（用户原话 · 2026-10-26）

用户原话（经游戏策划转达）：「本版就要把 XTR/爆裂/陷阶也写进统一判定序」。  
纪律：**同一局只计一种终结**；禁止叠分。Feel85 冻结常数不动。  
计分仍服从 §9：**凡出界胜 +3**；其余唯一胜 **+2**；平局各 **+1**。

### 11.1 优先级（高 → 低，取最高一种）

| 序 | 终结代号 | 触发（机制定义） | 分 | 与现网 Reason 关系 |
|----|----------|------------------|----|-------------------|
| 1 | **RINGOUT**（含 **XTR** 标签） | 唯一胜者因出界成立（`ringout`） | **+3** | 物理 Reason=`ringout`。若本局满足 XTR 条件（见 11.2），结算标签=`XTR`，**分值仍 +3**（不加第四档） |
| 2 | **BURST** 爆裂 | 一方棘轮/结构耐久耗尽且未同时出界胜 | **+2** | 现 UE **未实装**；实装后 Reason=`burst` |
| 3 | **TRAP** 陷阶 | 在陷阶区被判定磨停/罚停，且更高序未成立 | **+2** | 现 UE **未实装**；实装后 Reason=`trap` |
| 4 | **SPINOUT** 停转 | `Spin ≤ 0.02` 先停者负 | **+2** | Reason=`spinout`（已有） |
| 5 | **TIMEOUT** 超时动量 | 打满 60s 双方仍在转 | **+2** 或各 **+1** | Reason=`timeout`；`M=|V|×Mass`，近乎相等则 DRAW 各 +1 |

同时满足多条时：**只取表中序号更小者**；其余作废，不记分、不进 HUD 第二死因。

双方同时出界 / 同时爆裂 / 同时停转等 → **DRAW**，各 +1（不进入上方胜者分）。

### 11.2 XTR 与普通出界（展示层，不计额外分）

- **物理层**：结束原因只有 `ringout`（出界门控），不单开物理常数。  
- **计分层标签**：在 `ringout` 已成立且存在唯一胜者时：  
  - 若「加速技有效命中后 **T** 秒内，被命中方因此局出界」→ 标签 **XTR**（建议默认 **T=2.5s**，写盘前可再锁）  
  - 否则标签 **OVR**（普通出界）  
- **分值**：XTR 与 OVR **均为 +3**（用户已否决「仅 XTR +3」）。  
- **现状**：UE 尚无加速技事件时，不得把凡 `ringout` 标成 XTR；一律 OVR/+3，或 HUD 只写出界。

### 11.3 与旧单序的衔接

旧试作序 `ringout → spinout → timeout` **仍然成立**，本表在 ringout 与 spinout 之间插入尚未实装的 **BURST、TRAP** 槽位，避免日后叠分争论。

### 11.4 验收（机制）

- [ ] 任一局结算只有一个 `end_reason`（或 DRAW）  
- [ ] `ringout` → 胜方 +3；`spinout`/`timeout` 胜 → +2；DRAW → 各 +1  
- [ ] 同时 ringout+spinout 窗口只记 ringout  
- [ ] 无加速技构建中：禁止出现 score_tag=XTR  
- [ ] Feel85 四常数与 60s 硬墙未改
